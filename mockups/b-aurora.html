Amazon Web Services Guide

Self-contained reference for AWS — infrastructure, IAM, compute, and the Bedrock AI/ML stack.

Mental model & global infrastructure

AWS is organized as regions, availability zones, and edge locations. Think in failure domains first — design for zonal isolation, then regional recovery. The control plane and data plane have different reliability contracts.

Most production systems span at least two AZs. Multi-region is a deliberate cost and complexity trade for true disaster recovery.

Identity & access (IAM)

Everything in AWS is a principal acting on a resource under a policy. Prefer roles over long-lived keys, and scope permissions to the smallest action set that still works.

Compute & containers

EC2 is the substrate. EKS and ECS orchestrate containers; Fargate removes node management. Lambda fits event-driven work with hard duration limits.
