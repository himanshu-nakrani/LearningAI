Part 0 — How to read this & the big picture

All three clouds offer roughly the same shape of AI stack: pre-built APIs at the bottom, a foundation-model platform in the middle, and a full custom-ML platform on top — wrapped with infrastructure, safety, and assistants. They differ in which models they host, how mature each layer is, and what they integrate with.

The common three-layer shape

+----------------------------------------------------------+ | ASSISTANTS Amazon Q | Copilot | Gemini (apps) | +----------------------------------------------------------+ | GENERATIVE Bedrock | Azure OpenAI | Vertex AI + | | AI + AGENTS + AgentCore | + AI Foundry | Gemini | +----------------------------------------------------------+ | CUSTOM ML SageMaker | Azure ML | Vertex AI | +----------------------------------------------------------+ | PRE-BUILT Rekognition| AI Services | Vision/Speech | | AI APIs Transcribe | (Cognitive) | /NL/Doc AI | +----------------------------------------------------------+ | INFRA Trainium/ | ND/NC GPU VMs | TPUs + GPUs | | Inferentia + GPU | | | +----------------------------------------------------------+ AWS AZURE GCP

The one-line positioning

AWSAzureGCP
Broadest model choice via Bedrock; deepest overall service catalog; strong for agentic on AWS infra. Privileged OpenAI access (GPT, o-series) + best enterprise/Microsoft 365 integration. Best in-house models (Gemini), tight data+AI integration (BigQuery), and custom silicon (TPUs).
The honest summary For most workloads, all three are capable — the "best" choice usually follows your existing cloud, data gravity, and team skills rather than a decisive AI feature gap. The real differentiators: Azure for OpenAI models + Microsoft shops, GCP for Gemini + data-heavy/analytics-heavy AI, AWS for model breadth + the widest surrounding ecosystem.

How to think about it

"I want OpenAI's GPT / o-series with enterprise controls" -> AZURE OpenAI (the privileged path to these models) "I want Anthropic Claude, or the widest model selection under one API, inside AWS" -> AWS Bedrock "I want Google's Gemini (strong multimodal, long context) and tight ties to BigQuery/data" -> GCP Vertex AI Note: Claude is available on BOTH Bedrock and Vertex. Llama/Mistral/open models are available on all three.
Models are increasingly multi-cloud The big open and partner models (Llama, Mistral, and even Anthropic's Claude) show up on multiple clouds. The truly exclusive ties are OpenAI's GPT/o-series → Azure, and Gemini → GCP. If a specific frontier model is a hard requirement, that often decides the cloud. Otherwise, model availability is rarely the bottleneck.

Part 3 — Managed RAG & vector search

RAG (retrieve your data, then generate a grounded answer) is the most common GenAI pattern. Each cloud offers a managed path so you don't hand-build the pipeline.

PieceAWSAzureGCP
Managed RAGBedrock Knowledge Bases (ingest → embed → retrieve → ground)Azure AI Search + Azure OpenAI "on your data"Vertex AI Search / RAG Engine
Vector storeOpenSearch, Aurora/RDS pgvector, Neptune, MemoryDB, Pinecone (3rd-party)Azure AI Search (vector + keyword + semantic ranking)Vertex AI Vector Search, AlloyDB/Cloud SQL pgvector
Hybrid searchOpenSearch (vector + BM25)Built into Azure AI Search (a core strength)Vertex AI Search (semantic + keyword)
Best-fit when…You're AWS-centric and want managed end-to-end RAG with ClaudeYou want strong out-of-box hybrid retrieval + OpenAI generationYour knowledge lives in GCP data services / you want Gemini grounding

The same architecture, three flavors

GENERIC RAG (same everywhere): docs -> chunk -> embed -> vector store query -> embed -> retrieve top-K -> LLM grounds answer AWS: S3 -> Bedrock Knowledge Base -> OpenSearch -> retrieve_and_generate (Claude) + Guardrails AZURE: Blob -> Azure AI Search index (vector+keyword) -> Azure OpenAI "on your data" (GPT) + Content Safety GCP: GCS -> Vertex AI Search / Vector Search -> Gemini grounding + safety filters
Azure AI Search is a quiet strength Azure's retrieval engine has mature hybrid search (vector + keyword + semantic reranking) in a single managed service, which is often the hardest part of RAG to get right. If retrieval quality is your priority and you're flexible on cloud, it's worth a look. All three, though, can produce excellent RAG with proper chunking and reranking.

AWS AgentCore in a bit more depth

AgentCore = "managed infrastructure for agents" (bring any framework + any model): Runtime -> serverless, secure agent hosting/scaling Gateway -> expose APIs/Lambdas as agent tools (MCP) Memory -> short- & long-term memory store Identity -> agent auth & scoped access to resources Browser -> managed headless browser tool Code Interp.-> sandboxed code execution Observability -> trace every reason/act/observe step Relevant if you're building production agents on AWS: it removes undifferentiated plumbing while keeping you free to use LangGraph/CrewAI/Strands and any model.
Agent tooling is young and moving fast These managed agent services are evolving rapidly; capabilities and names shift between releases. Emerging open standards — MCP (Model Context Protocol) for tools and A2A (Agent-to-Agent) for agent interop — are being adopted across clouds, which reduces lock-in. Validate the current feature set before committing, and keep your agent logic portable where you can.

TPUs vs Trainium vs GPUs NVIDIA GPUs are the portable default everywhere and have the broadest framework support. Google TPUs are the most mature custom AI chips and can offer better price/performance for large-scale training/inference (especially JAX/TensorFlow, increasingly PyTorch). AWS Trainium/Inferentia target cost savings for supported models. Custom silicon trades some portability for efficiency — worth it only at meaningful scale.

Guardrails are necessary, not sufficient All three offer comparable input/output filtering, PII redaction, and prompt-injection defenses — apply them on both the way in and the way out. But platform guardrails don't replace your own architecture-level controls: least-privilege tool permissions, human-in-the-loop for high-impact actions, sandboxing, and audit logging. Treat model output and any external content as untrusted regardless of cloud.

Part 10 — Pricing models compared

GenAI pricing is broadly similar in shape across clouds; the absolute numbers shift constantly, so reason about the model, not the exact price.

How foundation-model usage is billed (all three)

PER-TOKEN (pay as you go): cost = input_tokens * rate_in + output_tokens * rate_out - varies by model (bigger/smarter = pricier) - output tokens usually cost more than input - good for variable / low-to-medium volume PROVISIONED / RESERVED THROUGHPUT: - reserve dedicated capacity for steady high volume - Bedrock: Provisioned Throughput - Azure OpenAI: PTUs (Provisioned Throughput Units) - Vertex: provisioned throughput / committed use - predictable cost + guaranteed capacity at scale
LeverAWSAzureGCP
On-demand tokensBedrock per-tokenAzure OpenAI per-tokenVertex per-token (per 1K chars/tokens)
Reserved capacityProvisioned ThroughputPTUsProvisioned throughput
Prompt cachingSupported (cuts cost/latency)SupportedContext caching
Batch discountBatch inference (lower price)Batch APIBatch prediction
Compute commitmentsSavings Plans / RIs / SpotReservations / Savings Plans / SpotCUDs / sustained-use / Spot
Cost-control levers are universal Regardless of cloud: pick the smallest model that meets quality, cache stable prompt prefixes, batch where latency allows, trim context (fewer tokens), cap output length, and reserve throughput only for steady high volume. Agents multiply token usage (many calls per task) — budget and cap them. These habits move cost far more than the cloud you pick.

Part 11 — Strengths, weaknesses & how to choose

AWSAzureGCP
Strengths Widest model choice (Bedrock), deepest overall catalog, mature agentic infra (AgentCore), biggest ecosystem & market share Privileged OpenAI access, best enterprise/Microsoft 365 + Entra integration, strong hybrid retrieval (AI Search) Best in-house models (Gemini), superb data+AI integration (BigQuery ML), mature TPUs, strong Kubernetes/data heritage
Weaknesses Breadth → complexity; many overlapping services; no first-party frontier LLM as strong as GPT/Gemini Tied closely to OpenAI's roadmap; smaller non-OpenAI model story; can be Microsoft-centric Smaller enterprise footprint & service breadth than AWS; fewer regions; sales/enterprise maturity behind AWS/Azure
Pick if… You're on AWS, want model flexibility (esp. Claude), or building production agents in an AWS estate You run Microsoft 365 / .NET / AD, or you specifically need OpenAI GPT & o-series with enterprise governance Your workloads are data/analytics-heavy, you want Gemini, or you value TPUs & BigQuery-native AI

A decision flow

Already heavily on one cloud? -> usually stay there (data gravity, skills, billing, network egress costs dominate). AI parity is close. Need a SPECIFIC frontier model? OpenAI GPT / o-series -> Azure Google Gemini -> GCP Anthropic Claude -> AWS Bedrock or GCP Vertex Open models (Llama...) -> any of the three Workload shape? Data/analytics + AI -> GCP (BigQuery + Vertex) Microsoft/enterprise -> Azure Broadest services/agents on existing AWS -> AWS Multi-cloud / avoid lock-in? -> keep app logic portable; use open models, MCP/A2A, and abstract the model provider behind an interface.
Data gravity and egress usually decide Moving large datasets between clouds is slow and expensive (egress fees). In practice, your AI runs best next to your data. Unless a specific model is a hard requirement, the pragmatic choice is the cloud where your data and team already are — the AI capabilities are close enough that integration and operational factors dominate.

What's the same everywhere (so don't over-optimize)

  • All three deliver foundation models via a managed API with data isolation and fine-tuning.
  • All offer managed RAG, vector search, and agent frameworks.
  • All have mature, comparable MLOps platforms.
  • All provide the full set of pre-built AI APIs (vision, speech, language, docs).
  • All bill tokens on-demand + offer reserved throughput, caching, and batch discounts.
  • All offer guardrails (content filtering, PII, prompt-injection, grounding).
  • Open models (Llama, Mistral) and emerging standards (MCP, A2A) run across all three.

What actually differs (so focus here)

  • Exclusive frontier models: GPT/o-series → Azure; Gemini → GCP.
  • Ecosystem fit: Microsoft → Azure; data/analytics → GCP; breadth → AWS.
  • Custom silicon maturity: TPUs (GCP) most proven; Trainium/Inferentia (AWS) for cost.
  • Retrieval maturity: Azure AI Search's hybrid search is notably strong.
  • Agent runtime approach: AWS AgentCore's framework-agnostic modular runtime.
Final advice Don't pick a cloud for a single AI feature — features converge fast and parity is the norm. Pick for data gravity, existing skills, ecosystem fit, and the one or two capabilities that are genuinely exclusive or clearly ahead (a specific model, TPUs, OpenAI access, BigQuery-native AI). Keep your application logic portable (open models, MCP/A2A, a model-provider abstraction) so you preserve optionality as the landscape keeps shifting.
