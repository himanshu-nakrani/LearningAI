Part 0 — How to use this guide & interview strategy

Most basic-to-medium interview problems are variations on a small set of patterns. Once you recognize the pattern, the solution follows. This guide teaches you to map a problem to its pattern, then implement cleanly.

The interview loop (say this out loud)

  1. Clarify — restate the problem, ask about input size, types, duplicates, empty input, sorted or not.
  2. Examples — walk a small example by hand. Find an edge case.
  3. Brute force — state the obvious solution and its complexity. Never stay silent.
  4. Optimize — name the pattern that removes the bottleneck (hashing, two pointers, etc.).
  5. Code — write clean code, talk while you type.
  6. Test — dry-run your code on the example and an edge case.
  7. Complexity — state final time and space.
The single most important habit Always state the brute force first with its complexity, then improve it. Interviewers grade your problem-solving process, not just the final answer. A working brute force beats a broken clever solution.

Part 1 — Big-O & complexity analysis FOUNDATION

Big-O describes how runtime or memory grows as input size n grows. You drop constants and lower-order terms: O(2n + 5) becomes O(n). We care about the shape of growth, not exact counts, because for large inputs the fastest-growing term dominates everything else.

Think of it as answering: "If I double the input, what happens to the running time?" For O(n) it doubles. For O(n²) it quadruples. For O(log n) it barely moves. That single question separates a solution that scales from one that falls over in production.

How the curves diverge as n grows

The chart below shows roughly how many operations each complexity class needs. Notice how O(n²) and O(2ⁿ) explode while O(log n) stays nearly flat — this is why the "right" algorithm matters far more than fast hardware.

How to count complexity in practice

Two rules cover almost everything you'll meet:

  • Sequential code adds: a loop followed by another loop is O(n) + O(n) = O(n).
  • Nested code multiplies: a loop inside a loop is O(n) × O(n) = O(n²).
for i in range(n): # outer runs n times for j in range(n): # inner runs n times each work() # => n * n = n^2 total for i in range(n): # this loop: n work() for j in range(n): # plus this: n work() # total: 2n -> O(n)

When a loop's bound shrinks by a constant factor each step (halving, like binary search), that's the signature of O(log n) — you can only halve n about log₂(n) times before reaching 1.

Time vs space

Complexity comes in two flavors. Time is how many operations run. Space is how much extra memory you allocate beyond the input. A hash map that stores every element is O(n) space; reversing an array with two pointers is O(1) space. Interviewers often ask for both, and sometimes ask you to trade one for the other.

Amortized vs worst case

A Python list append is O(1) amortized: most appends are constant, but occasionally the list resizes (copy all elements). Averaged over many appends, it's still O(1). Mention "amortized" when discussing dynamic arrays and hash tables.

Common complexity traps
  • String concatenation in a loop is O(n²) in many languages — build a list and join.
  • x in list is O(n); x in set is O(1). Don't use a list as a membership test.
  • Slicing arr[i:j] in Python creates a copy — O(j−i), not free.
  • Recursion uses O(depth) stack space even if you allocate nothing else.

Part 2 — Arrays & strings EASY

Arrays (Python list) and strings are the most common interview substrate. Strings in Python are immutable — any "modification" creates a new string.

How an array is laid out in memory

An array stores elements in one contiguous block. Because every element is the same size and they sit side by side, the computer can jump straight to element i by computing base_address + i × element_size — no scanning required. That's why indexing is O(1).

index: 0 1 2 3 4 +-----+-----+-----+-----+-----+ list = | 3 | 1 | 4 | 1 | 5 | +-----+-----+-----+-----+-----+ addr: 100 104 108 112 116 (4 bytes each) a[3] -> base(100) + 3*4 = 112 -> read directly. O(1)

The flip side: inserting or deleting at the front means every later element must shift one slot to fill or open the gap — that's the O(n) cost. Appending at the end is cheap because nothing moves (until the block fills up and the list resizes).

insert 'x' at front: +-----+-----+-----+-----+ every element before | 1 | 4 | 1 | 5 | slides right -> +-----+-----+-----+-----+ O(n) work +-----+-----+-----+-----+-----+ after | x | 1 | 4 | 1 | 5 | +-----+-----+-----+-----+-----+

Worked example: reverse a string in place (char array)

def reverse(s: list[str]) -> None:
    left, right = 0, len(s) - 1
    while left < right:
        s[left], s[right] = s[right], s[left]   # swap
        left += 1
        right -= 1
# O(n) time, O(1) space
Python swap trick a, b = b, a swaps without a temp variable. Use it freely — it's idiomatic and clear.

Part 3 — Hashing (dicts & sets) PATTERN EASY

Hash maps trade space for time: O(1) average lookup, insert, and delete. This single idea converts many O(n²) problems into O(n). If a problem asks "have I seen X?" or "how many times?", reach for a dict or set.

How a hash map works

A hash function turns a key into an array index. The value is stored in a backing array (the "buckets") at that index. Looking up a key recomputes the hash and jumps straight to the bucket — no scanning. That's the O(1) magic.

key "apple" --hash()--> 3251 --% 8--> bucket 3 key "pear" --hash()--> 9982 --% 8--> bucket 6 buckets: 0: [ ] 1: [ ] 2: [ ] 3: [ "apple" -> 5 ] 4: [ ] 5: [ ] 6: [ "pear" -> 2 ] 7: [ ] lookup("apple"): hash -> bucket 3 -> found in O(1)

Collisions happen when two keys hash to the same bucket. Python handles this internally (open addressing), so multiple keys can coexist. Collisions are why lookups are O(1) average, not guaranteed worst case — but in practice you treat dict operations as constant time.

The core trick: "remember as you go" Most hash-map problems work in one pass: as you scan the array, you record what you've seen in a dict, and for each new element you check whether its "complement" or partner is already recorded. One loop, O(n), instead of comparing every pair in O(n²).

Python tools

from collections import Counter, defaultdict

seen = set()                 # membership in O(1)
count = {}                   # plain dict

c = Counter("aabbbc")        # {'a':2,'b':3,'c':1}
c.most_common(2)             # [('b',3),('a',2)]

d = defaultdict(list)        # missing key -> []
d[key].append(val)           # no KeyError

d = defaultdict(int)         # missing key -> 0
d[key] += 1                  # frequency counting

Canonical problem: Two Sum

Given an array and a target, return indices of two numbers that add to target.

def two_sum(nums, target):
    seen = {}                      # value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []
# Brute force: O(n^2). With hashing: O(n) time, O(n) space.

Walking through nums = [2, 7, 11, 15], target = 9:

i=0 x=2 need=7 7 in seen? no -> store {2:0} i=1 x=7 need=2 2 in seen? YES -> return [0, 1] (seen[2]=0, current i=1) We never had to compare 7 against 11 or 15. Each element is checked once against a O(1) lookup.

Other classic hashing problems

  • Group anagrams — key each word by its sorted letters (or letter-count tuple).
  • Contains duplicate — len(set(nums)) != len(nums).
  • First unique character — count with Counter, then find the first with count 1.
  • Intersection of two arrays — set(a) & set(b).
When NOT to use a hash map If the array is sorted, two pointers may be O(1) space vs the hash map's O(n). And dict keys must be hashable — lists can't be keys, but tuples can.

Part 4 — Two pointers PATTERN EASY

Use two indices that move toward each other (or in the same direction) to avoid a nested loop. Works best on sorted arrays or when comparing from both ends.

Why it works: the sorted-array insight

On a sorted array, the sum of the two ends tells you which way to move. If the sum is too small, the only way to increase it is to move the left pointer right (to a bigger value). If it's too big, move the right pointer left. Each move permanently eliminates one candidate, so you scan the whole array just once — O(n) instead of O(n²).

target = 9 sorted: [1, 2, 4, 7, 11, 15] lo hi step 1: 1 + 15 = 16 > 9 too big -> move hi left [1, 2, 4, 7, 11, 15] lo hi step 2: 1 + 11 = 12 > 9 too big -> move hi left [1, 2, 4, 7, 11, 15] lo hi step 3: 1 + 7 = 8 < 9 too small -> move lo right [1, 2, 4, 7, 11, 15] lo hi step 4: 2 + 7 = 9 == 9 FOUND! The pointers met the answer from both sides.

Variant A: opposite ends (converging)

# Two Sum on a SORTED array, O(1) space
def two_sum_sorted(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return [lo, hi]
        elif s < target:
            lo += 1          # need bigger sum
        else:
            hi -= 1          # need smaller sum
    return []

Variant B: same direction (fast/slow, read/write)

# Remove duplicates from sorted array in place
def remove_dups(nums):
    if not nums:
        return 0
    write = 1
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]
            write += 1
    return write             # new length

Classic two-pointer problems

  • Valid palindrome — converge from both ends, skip non-alphanumerics.
  • 3Sum — sort, fix one element, two-pointer the rest MEDIUM.
  • Container with most water — converge, move the shorter wall.
  • Merge two sorted arrays — pointer per array.
  • Move zeroes — read/write pointers.
Decision rule Sorted input + "find pair/triplet with property" → two pointers. Unsorted + "have I seen it" → hash map. If sorting is allowed and you need O(1) space, sort then two-pointer.

Part 5 — Sliding window PATTERN MEDIUM

For problems about a contiguous subarray or substring that satisfies a condition. Instead of recomputing every window from scratch (O(n²)), grow the right edge and shrink the left edge, maintaining a running state — O(n).

The key idea: don't throw away work

A brute-force approach recomputes each window independently. Sliding window reuses the previous window's result: when the window slides right by one, you add the entering element and subtract the leaving one. The shared middle is never recomputed.

Brute force (recompute each window of size 3): [2, 1, 5, 1, 3, 2] \_____/ sum = 8 (3 adds) \_____/ sum = 7 (3 adds again!) \_____/ sum = 9 (3 adds again!) Sliding window (reuse the overlap): [2, 1, 5, 1, 3, 2] \_____/ sum = 8 \_____/ sum = 8 - 2 + 1 = 7 (1 add, 1 sub) \_____/ sum = 7 - 1 + 3 = 9 (1 add, 1 sub) Same answers, but O(n) instead of O(n*k).

Fixed-size window

# Max sum of any subarray of size k
def max_sum_k(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]   # add new, drop old
        best = max(best, window)
    return best

Variable-size window (the general template)

# Longest substring without repeating characters
def longest_unique(s):
    seen = set()
    left = 0
    best = 0
    for right, c in enumerate(s):
        while c in seen:               # shrink until valid
            seen.remove(s[left])
            left += 1
        seen.add(c)
        best = max(best, right - left + 1)
    return best
# O(n) time, O(min(n, charset)) space

The mental model

[ . . . ( window ) . . . ] left right--> 1. Expand right to include new element. 2. While window is invalid, advance left. 3. Record the answer when window is valid.

Trace: longest substring without repeats

On s = "abcabcbb", watch the window stretch until a duplicate forces the left edge forward:

"a b c a b c b b" ^ left=0 right=0 window="a" best=1 a^ window="ab" best=2 a b^ window="abc" best=3 a b c^ 'a' repeats! shrink from left ^a b c window="bca" (dropped first a) best=3 ...continues, window never exceeds 3 unique chars The window only ever moves forward -> each character is added once and removed at most once -> O(n).

Classic sliding-window problems

  • Longest substring without repeating characters
  • Minimum size subarray sum ≥ target
  • Longest substring with at most K distinct characters
  • Permutation in string / find all anagrams (fixed window + counts)
  • Max consecutive ones after flipping K zeros

Part 6 — Prefix sum PATTERN MEDIUM

Precompute cumulative sums so any range sum is O(1). prefix[i] = sum of first i elements, so sum(a..b) = prefix[b+1] - prefix[a].

The picture

Each prefix entry holds the total of everything before it. To get the sum of a slice, subtract the prefix at the start from the prefix just past the end — the shared front cancels out, leaving exactly the middle.

nums: [ 2, 4, 1, 3, 5 ] index: 0 1 2 3 4 prefix: [ 0, 2, 6, 7, 10, 15 ] index: 0 1 2 3 4 5 (prefix[i] = sum of nums[0..i-1]) sum of nums[1..3] (=4+1+3=8): prefix[4] - prefix[1] = 10 - 2 = 8 |__ everything up to index 3 __| |__ minus everything before index 1 __| One subtraction, O(1), no matter how wide the range.
# Range sum queries
def build_prefix(nums):
    prefix = [0] * (len(nums) + 1)
    for i, x in enumerate(nums):
        prefix[i + 1] = prefix[i] + x
    return prefix

# sum of nums[a..b] inclusive:
# prefix[b + 1] - prefix[a]

Killer combo: prefix sum + hash map

Count subarrays whose sum equals K. Track running sum; if running - K was seen before, those positions form valid subarrays.

def subarray_sum_k(nums, k):
    count = 0
    running = 0
    seen = {0: 1}            # sum 0 occurs once (empty prefix)
    for x in nums:
        running += x
        count += seen.get(running - k, 0)
        seen[running] = seen.get(running, 0) + 1
    return count
# O(n) time and space
Why {0: 1}? It accounts for subarrays that start at index 0. Without it you'd miss the case where the prefix itself equals K.

Part 7 — Stack & queue PATTERN EASY

A stack is LIFO (last in, first out). A queue is FIFO (first in, first out). In Python, use a list for a stack and collections.deque for a queue (front pops are O(1) on a deque, O(n) on a list).

Visualizing the two

STACK (LIFO) QUEUE (FIFO) push/pop same end add back, remove front push v ^ pop front back | | remove | | add +-----+ v v | C | <- top +---+---+---+---+---+ +-----+ | A | B | C | D | E | | B | +---+---+---+---+---+ +-----+ ^ ^ | A | popleft() append() +-----+ Last in (C) First in (A) comes out first comes out first

Stacks model anything with nesting or "undo" semantics: matching brackets, function call frames, browser back button, expression evaluation. Queues model anything processed in arrival order: task schedulers, BFS traversal, buffering.

stack = []
stack.append(x)      # push
stack.pop()          # pop top
stack[-1]            # peek

from collections import deque
q = deque()
q.append(x)          # enqueue back
q.popleft()          # dequeue front, O(1)

Canonical stack problem: valid parentheses

def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for c in s:
        if c in pairs.values():
            stack.append(c)
        elif c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False
    return not stack
# O(n) time and space

Trace on "([])" — every closer must match the most recent opener, which is exactly what the top of the stack holds:

'(' open -> push stack: [ ( ] '[' open -> push stack: [ (, [ ] ']' close -> pop '[' matches ']' ok stack: [ ( ] ')' close -> pop '(' matches ')' ok stack: [ ] end: stack empty -> VALID On "([)]" the ')' would pop '[' -> mismatch -> INVALID. The stack naturally enforces correct nesting order.

Monotonic stack: next greater element

A stack that stays sorted (increasing or decreasing) solves "next greater/smaller" in O(n).

def next_greater(nums):
    res = [-1] * len(nums)
    stack = []               # holds indices, decreasing values
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x
        stack.append(i)
    return res

Other classics

  • Min stack (track min alongside each push)
  • Evaluate reverse Polish notation
  • Daily temperatures (monotonic stack)
  • Implement queue using two stacks (and vice versa)

Part 8 — Linked lists PATTERN MEDIUM

A chain of nodes, each pointing to the next. No O(1) random access, but O(1) insert/delete given a node. Interview favorites because pointer manipulation reveals careful thinking.

The structure

head | v +----+----+ +----+----+ +----+----+ | 3 | *--+--> | 7 | *--+--> | 9 | / | (/ = None) +----+----+ +----+----+ +----+----+ val next val next val next Unlike an array, nodes can live anywhere in memory. You can only reach node 3 by following 'next' from head. No index jump -> finding the k-th node is O(k).

The tradeoff vs an array: linked lists make insertion/deletion at a known position O(1) (just rewire pointers, nothing shifts), but you lose O(1) random access and cache-friendly contiguous storage.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

The two techniques that solve most LL problems

1. Dummy head (simplifies edge cases)

# Reverse a linked list
def reverse(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next       # save next
        cur.next = prev      # flip pointer
        prev = cur           # advance prev
        cur = nxt            # advance cur
    return prev              # new head
# O(n) time, O(1) space

Reversal works by flipping one pointer at a time. The trick is saving next before you overwrite it, or you lose the rest of the list:

start: None 3 -> 7 -> 9 -> None cur step 1: None <- 3 7 -> 9 prev=3, cur=7 step 2: None <- 3 <- 7 9 prev=7, cur=9 step 3: None <- 3 <- 7 <- 9 prev=9, cur=None cur is None -> stop. New head = prev = 9. Result: 9 -> 7 -> 3 -> None

2. Fast & slow pointers (Floyd's)

Two pointers move at different speeds. Because the fast one covers twice the distance, it reaches the end when the slow one is at the middle — and on a cycle, the fast one eventually laps the slow one and they collide.

Finding the middle (fast = 2x slow): 1 -> 2 -> 3 -> 4 -> 5 -> None s,f step1: s=2 f=3 step2: s=3 f=5 f at end -> slow(3) is the middle. Cycle detection (the tortoise and hare): 1 -> 2 -> 3 -> 4 ^ | +----------+ (4 points back to 3) If there's a loop, fast can never "escape" past slow; it gains 1 step per move and must eventually land on it. If there's no loop, fast simply hits None.
# Detect a cycle
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next         # +1
        fast = fast.next.next    # +2
        if slow is fast:
            return True
    return False

# Find the middle node
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow

Classic linked-list problems

  • Reverse a linked list (iterative + recursive)
  • Merge two sorted lists
  • Detect cycle / find cycle start
  • Remove Nth node from end (two pointers, gap of N)
  • Find middle, check palindrome
Always guard None Before accessing node.next, confirm node isn't None. The most common linked-list bug is dereferencing a null pointer at the tail.

Part 9 — Binary search PATTERN MEDIUM

On a sorted array, halve the search space each step: O(log n). The hard part is getting the boundaries right.

Why halving is so powerful

Each comparison eliminates half the remaining candidates. Searching 1,000,000 items takes only about 20 steps, because 2²⁰ ≈ 1,000,000. Doubling the data adds just one step. That's the difference between log and linear.

search target = 7 in sorted [1, 3, 5, 7, 9, 11, 13] 0 1 2 3 4 5 6 step 1: lo=0 hi=6 mid=3 -> nums[3]=7 == 7 FOUND search target = 11: step 1: lo=0 hi=6 mid=3 -> nums[3]=7 < 11 -> go right [_, _, _, _, 9, 11, 13] lo=4 hi=6 step 2: lo=4 hi=6 mid=5 -> nums[5]=11 == 11 FOUND Each step throws away half the array: 7 elements -> 3 -> 1 ... ~log2(7) ≈ 3 steps max.
# Standard: find target index, else -1
def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

Find the boundary (leftmost position)

More useful than exact match: "first index where condition is true." Python's bisect does this for you.

import bisect
i = bisect.bisect_left(nums, target)   # first index >= target
i = bisect.bisect_right(nums, target)  # first index > target

Binary search on the answer

When the array isn't the thing you search — you search a range of possible answers and check feasibility. Examples: minimum eating speed (Koko bananas), split array largest sum, capacity to ship packages in D days.

# Template
def min_feasible(lo, hi, feasible):
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid         # mid works, try smaller
        else:
            lo = mid + 1     # mid too small
    return lo
Overflow & infinite loops Use mid = lo + (hi - lo) // 2 in languages with fixed-size ints. In Python integers are unbounded so (lo + hi) // 2 is fine. To avoid infinite loops, make sure the search space strictly shrinks each iteration.

Know merge sort's merge step

Merge sort splits the array in half repeatedly until each piece is a single element (trivially sorted), then merges pairs back together in order. The split tree has log n levels, and each level does O(n) merging work — hence O(n log n).

[5, 2, 8, 1] / \ split [5, 2] [8, 1] / \ / \ split [5] [2] [8] [1] \ / \ / merge (compare & weave) [2, 5] [1, 8] \ / merge [1, 2, 5, 8] Each level touches all n elements (O(n)), and there are log n levels -> O(n log n).

The merge step itself walks two already-sorted lists with one pointer each, always taking the smaller front element:

def merge(a, b):
    res = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            res.append(a[i]); i += 1
        else:
            res.append(b[j]); j += 1
    res.extend(a[i:])
    res.extend(b[j:])
    return res

Part 11 — Recursion & backtracking PATTERN MEDIUM

Recursion: a function calls itself on a smaller input until a base case. Backtracking: build a candidate solution incrementally, abandon ("backtrack") as soon as it can't lead to a valid answer.

Recursion anatomy

  • Base case — when to stop (prevents infinite recursion).
  • Recursive case — reduce the problem and call yourself.
  • Combine — assemble sub-results.
def factorial(n):
    if n <= 1:           # base case
        return 1
    return n * factorial(n - 1)   # recursive case

The backtracking template

def backtrack(path, choices):
    if is_solution(path):
        result.append(path[:])     # copy!
        return
    for choice in choices:
        if not valid(choice):
            continue
        path.append(choice)        # choose
        backtrack(path, next_choices)
        path.pop()                 # un-choose (backtrack)

Worked example: subsets

def subsets(nums):
    res = []
    def bt(start, path):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            bt(i + 1, path)
            path.pop()
    bt(0, [])
    return res
# 2^n subsets, so O(n * 2^n)

Backtracking explores a decision tree: at each node you choose to include an element or not, recurse, then undo the choice and try the next branch. The "un-choose" (path.pop()) is what lets one path list be reused across the whole tree.

subsets of [1, 2, 3] -- branch = "add nums[i]" [] / | \ +1 +2 +3 [1] [2] [3] / \ | +2 +3 +3 [1,2] [1,3] [2,3] | +3 [1,2,3] Every node is recorded as a subset. We descend (choose), collect, then pop back up (un-choose) to try siblings. 8 = 2^3 subsets total.

Classic backtracking problems

  • Subsets, permutations, combinations
  • Combination sum
  • Generate parentheses
  • Word search (grid + backtracking)
  • N-Queens, Sudoku solver (harder)
Two recursion gotchas
  • Append a copy (path[:]) to results — otherwise later mutations corrupt stored answers.
  • Python's recursion limit is ~1000. For deep recursion, increase it or go iterative.

Part 12 — Trees & BST PATTERN MEDIUM

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

Anatomy of a binary tree

root (1) depth 0 / \ (2) (3) depth 1 / \ \ (4) (5) (6) depth 2 <- leaves have no children - root: the top node (1) - parent/child: 1 is parent of 2 and 3 - leaf: a node with no children (4, 5, 6) - height: longest root-to-leaf path (here, 2) - subtree: any node + all its descendants

The four traversals

TraversalOrderUse
Pre-orderNode, Left, RightCopy/serialize tree
In-orderLeft, Node, RightBST → sorted order
Post-orderLeft, Right, NodeDelete tree, compute height
Level-orderBFS by depthShortest path, by-level output

Same tree, four different visit orders. The DFS variants differ only in when you "visit" (record) the node relative to recursing into its children:

(1) / \ (2) (3) / \ (4) (5) Pre-order (Node,Left,Right): 1 2 4 5 3 In-order (Left,Node,Right): 4 2 5 1 3 Post-order (Left,Right,Node): 4 5 2 3 1 Level-order (top to bottom) : 1 2 3 4 5 In-order on a BST always yields sorted values -- remember this.
# DFS in-order (recursive)
def inorder(node, out):
    if not node:
        return
    inorder(node.left, out)
    out.append(node.val)
    inorder(node.right, out)

# BFS level-order (queue)
from collections import deque
def level_order(root):
    if not root: return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res

Binary Search Tree property

For every node: all values in the left subtree are smaller, all in the right are larger. This makes search/insert/delete O(h) where h is height (O(log n) if balanced). An in-order traversal of a BST yields sorted values — remember this.

(8) / \ (3) (10) / \ \ (1) (6) (14) search for 6: 8 -> 6 is smaller, go left 3 -> 6 is bigger, go right 6 -> found! (3 steps, not 6) Every comparison discards an entire subtree, just like binary search on an array -> O(height). Warning: an unbalanced BST degrades to a linked list, O(n).

Classic tree problems

  • Max depth / height, balanced check
  • Invert / mirror a tree
  • Same tree / symmetric tree
  • Lowest common ancestor
  • Validate BST (track min/max bounds)
  • Level-order, zigzag, right-side view (BFS variants)
  • Path sum, diameter of tree
Most tree problems are one traversal in disguise Decide: do I need top-down info (pass values down as parameters) or bottom-up info (return values up from children)? Height and diameter are bottom-up; path-from-root problems are top-down.

Part 13 — Graphs (BFS / DFS) PATTERN MEDIUM

A graph is nodes + edges. Represent it as an adjacency list (dict of node → neighbors). Trees and grids are special graphs.

Representing a graph

The graph: Adjacency list: 0: [1, 2] (0)---(1) 1: [0, 3] | | 2: [0, 3] (2)---(3) 3: [1, 2] An edge (0,1) appears in both 0's and 1's lists (undirected). For a directed graph, store only one way. Space: O(V + E) -- vertices plus edges.
from collections import defaultdict, deque
graph = defaultdict(list)
for u, v in edges:
    graph[u].append(v)
    graph[v].append(u)        # omit for directed

DFS vs BFS — two ways to explore

DFS plunges down one path as far as possible before backtracking (uses a stack / recursion). BFS explores all immediate neighbors first, then their neighbors, rippling outward in layers (uses a queue). BFS finds the shortest path in an unweighted graph because it reaches nodes in order of distance.

(A) / \ (B) (C) / \ \ (D) (E) (F) DFS from A (go deep first): A B D E C F dive A->B->D, back up, ->E, back up, ->C->F BFS from A (go wide first): A B C D E F layer 0: A layer 1: B C (distance 1 from A) layer 2: D E F (distance 2 from A)

DFS — go deep (recursion or stack)

def dfs(node, visited):
    if node in visited:
        return
    visited.add(node)
    for nbr in graph[node]:
        dfs(nbr, visited)

BFS — go wide (queue, finds shortest path in unweighted graphs)

def bfs(start):
    visited = {start}
    q = deque([start])
    while q:
        node = q.popleft()
        for nbr in graph[node]:
            if nbr not in visited:
                visited.add(nbr)
                q.append(nbr)

Grid traversal (very common)

# Number of islands: DFS flood fill
def num_islands(grid):
    rows, cols = len(grid), len(grid[0])
    count = 0
    def sink(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols or grid[r][c] != '1':
            return
        grid[r][c] = '0'                 # mark visited
        sink(r+1, c); sink(r-1, c)
        sink(r, c+1); sink(r, c-1)
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                count += 1
                sink(r, c)
    return count

Must-know graph topics

  • Connected components count (DFS/BFS/union-find)
  • Cycle detection (directed vs undirected)
  • Topological sort (course schedule) — Kahn's algorithm or DFS
  • Shortest path: BFS (unweighted), Dijkstra (weighted, heap)
  • Clone graph, word ladder
Always track visited Forgetting the visited set causes infinite loops on cyclic graphs. For grids, you can mark cells in place to save space.

Part 14 — Heaps / priority queue PATTERN MEDIUM

A heap gives O(1) access to the min (or max) and O(log n) insert/remove. Python's heapq is a min-heap. Use it for "top K", "Kth largest", "merge K lists", and streaming-median problems.

What a heap actually is

A binary heap is a complete binary tree where every parent is ≤ its children (min-heap). The smallest element is always at the root, so peeking the min is O(1). It's stored compactly in a plain array — no node objects — using index arithmetic to find parents and children.

min-heap tree: stored as array: (1) index: 0 1 2 3 4 5 / \ value: [1, 3, 2, 7, 4, 5] (3) (2) / \ / for node at index i: (7) (4)(5) parent = (i-1)//2 left = 2*i + 1 right = 2*i + 2 Root (index 0) is always the minimum. Insert/remove "bubble" an element up or down through ~log n levels to restore the order. O(log n).
import heapq
h = []
heapq.heappush(h, x)
smallest = heapq.heappop(h)      # removes & returns min
h[0]                             # peek min
heapq.heapify(nums)              # O(n) build in place

# Max-heap trick: negate values
heapq.heappush(h, -x)
largest = -heapq.heappop(h)

Kth largest element

def kth_largest(nums, k):
    h = nums[:k]
    heapq.heapify(h)             # min-heap of k elements
    for x in nums[k:]:
        if x > h[0]:
            heapq.heapreplace(h, x)
    return h[0]
# O(n log k) time, O(k) space

Top K frequent elements

def top_k_frequent(nums, k):
    count = Counter(nums)
    return heapq.nlargest(k, count.keys(), key=count.get)
Heap vs sort for "top K" Sorting is O(n log n); a size-K heap is O(n log k). When k ≪ n, the heap wins and uses less memory. For streaming data where you can't see everything at once, the heap is the only option.

Part 15 — Dynamic programming (intro) PATTERN MEDIUM

DP solves problems by breaking them into overlapping subproblems and storing each subproblem's answer (so you never recompute). Two signals: (1) "count the number of ways" or "find min/max", and (2) the same subproblem recurs.

Why DP works: kill the repeated work

Naive recursion for Fibonacci recomputes the same values exponentially many times. Memoizing each result collapses the call tree into a linear chain of unique subproblems.

Naive fib(5) -- same nodes computed over and over: fib(5) / \ fib(4) fib(3) / \ / \ fib(3) fib(2) fib(2) fib(1) / \ ... ... fib(2) fib(1) fib(2) appears 3 times! fib(1) appears 5 times! -> O(2^n) calls With memo -- each fib(k) computed once, then cached: fib(0) fib(1) fib(2) fib(3) fib(4) fib(5) 0 1 1 2 3 5 -> O(n) calls. Store once, reuse forever.

Two styles

  • Top-down (memoization) — recursion + cache. Natural to write.
  • Bottom-up (tabulation) — fill a table iteratively. Often faster, no recursion limit.

Fibonacci — the "hello world" of DP

# Top-down with memo
from functools import lru_cache
@lru_cache(None)
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)

# Bottom-up, O(1) space
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

The DP recipe

  1. Define the state — what does dp[i] mean? (e.g. "max sum ending at i").
  2. Recurrence — how does dp[i] relate to earlier states?
  3. Base case — the smallest subproblems.
  4. Order — fill so dependencies are ready.
  5. Answer — which cell holds the result?

Worked example: climbing stairs (= Fibonacci)

# Ways to reach step n taking 1 or 2 steps
def climb(n):
    if n <= 2: return n
    a, b = 1, 2
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b

Starter DP problems (1D → 2D)

  • Climbing stairs, house robber, min cost climbing stairs
  • Coin change (min coins), max subarray (Kadane's)
  • Longest increasing subsequence
  • 0/1 knapsack, partition equal subset sum
  • Unique paths in grid, longest common subsequence (2D)
  • Edit distance (2D, harder)

Kadane's algorithm (max subarray — know this cold)

def max_subarray(nums):
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)    # extend or restart
        best = max(best, cur)
    return best
# O(n) time, O(1) space

At each element you make one decision: extend the current subarray, or start fresh from here. You start fresh whenever the running sum has gone negative (it can only drag the next element down).

nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4] x=-2 cur=-2 best=-2 x= 1 cur=max(1,-1)=1 best=1 (restart: -2 was a drag) x=-3 cur=max(-3,-2)=-2 best=1 x= 4 cur=max(4,2)=4 best=4 (restart again) x=-1 cur=3 best=4 x= 2 cur=5 best=5 x= 1 cur=6 best=6 <- subarray [4,-1,2,1] x=-5 cur=1 best=6 x= 4 cur=5 best=6 Answer: 6. One pass, O(1) memory.
How to spot DP vs greedy If a locally optimal choice always leads to the global optimum, greedy works. If you need to consider multiple futures and pick the best, it's DP. When unsure, write the recursion first; if subproblems repeat, add memoization.

Part 16 — Greedy & intervals PATTERN MEDIUM

A greedy algorithm makes the locally best choice at each step. It's fast but only correct when the problem has the "greedy choice property." Interval problems are the most common greedy category.

Interval template: sort first

Sorting by start time means any overlap must be with the interval you just kept — you never have to look further back. Walk left to right; if the current interval starts before the last kept one ends, they overlap, so extend. Otherwise it's a new separate interval.

intervals: [1,3] [2,6] [8,10] [9,12] (already sorted by start) on a timeline: 1---3 2-------6 8----10 9------12 [1,3] and [2,6] overlap (2 <= 3) -> merge to [1,6] [8,10] and [9,12] overlap (9 <= 10) -> merge to [8,12] result: [1,6] [8,12] 1-----------6 8-------12
# Merge overlapping intervals
def merge(intervals):
    intervals.sort(key=lambda x: x[0])      # sort by start
    res = [intervals[0]]
    for start, end in intervals[1:]:
        if start <= res[-1][1]:              # overlap
            res[-1][1] = max(res[-1][1], end)
        else:
            res.append([start, end])
    return res

Non-overlapping intervals (remove fewest)

# Sort by END, greedily keep earliest-finishing
def erase_overlap(intervals):
    intervals.sort(key=lambda x: x[1])
    end = float('-inf')
    keep = 0
    for s, e in intervals:
        if s >= end:
            keep += 1
            end = e
    return len(intervals) - keep

Common greedy/interval problems

  • Merge intervals, insert interval
  • Non-overlapping intervals, meeting rooms (I & II)
  • Jump game (can you reach the end?)
  • Gas station, assign cookies
  • Activity selection
Greedy needs proof Greedy is wrong surprisingly often. If you can't argue why the local choice is safe, fall back to DP. The classic counterexample: coin change with coins [1, 3, 4] for amount 6 — greedy picks 4+1+1=3 coins, but 3+3=2 coins is better.

# Single number: every element appears twice except one
def single(nums):
    res = 0
    for x in nums:
        res ^= x        # pairs cancel out
    return res

Math you should remember
