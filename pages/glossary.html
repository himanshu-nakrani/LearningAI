Glossary

Brief definitions of the key concepts used across the guides. Each entry links to where the term is treated in depth.

Sections: AI/ML core · Agentic AI · LLM inference · Cloud AI services · Hardware · System design · Python · DSA

AI / ML core

Token
A subword unit produced by the tokenizer — the atomic input/output of an LLM. One token ≈ ¾ of an English word on average. Costs and context limits are measured in tokens. → AI Engineering · Part 1
Embedding
A dense vector that places text (or any item) in a high-dimensional space where geometric distance encodes semantic similarity. Sentence/document embeddings (from a dedicated embedding model) power RAG retrieval; internal token embeddings are a different, contextual concept. → AI Engineering · Part 5
Context window
The maximum number of tokens a model can attend to in a single request. Frontier models in 2026 commonly support 1M+ tokens (Gemini 2.5/3, Claude extended thinking, GPT-5). Cost and latency grow with used context, so retrieval-augmented generation is often preferable to stuffing the window. → AI Engineering · Part 2
RAG Retrieval-Augmented Generation
Architecture pattern: retrieve a small set of relevant documents from a vector or hybrid index, then prompt the LLM to answer using only that retrieved context. Reduces hallucination and lets a model stay current without retraining. → AI Engineering · Part 6
Chain-of-thought CoT
Prompting the model to produce intermediate reasoning steps before its final answer. In 2025-2026, frontier "reasoning models" (GPT-5 thinking, Claude extended thinking, Gemini thinking) internalize this and charge separately for thinking tokens. → AI Engineering · Part 3
Fine-tuning
Further training a base model on a smaller curated dataset to specialize it. Full fine-tuning updates all parameters; parameter-efficient variants (LoRA, QLoRA) update only a small adapter to keep the original frozen. → AI Engineering · Part 11
LoRA / QLoRA
LoRA (Low-Rank Adaptation) injects small trainable rank-decomposition matrices into a frozen base model — typically <1% of full parameters. QLoRA additionally quantizes the base to 4-bit so training fits on much smaller GPUs. → AI Engineering · Part 11
RLHF / DPO
Preference-based alignment. RLHF trains a reward model from human comparisons, then uses RL (PPO) to align the policy. DPO (Direct Preference Optimization) skips the reward model and optimizes preferences directly — simpler and now the more common path. → AI Engineering · Part 11
KV cache
Per-layer cached attention keys and values for already-generated tokens. The dominant memory cost during decoding — proportional to batch × layers × heads × hidden × sequence length × dtype. Caching it well (paging, prefix sharing) is most of inference optimization. → LLM Inference · Part 4
Quantization
Reducing weight (and sometimes activation/KV-cache) precision below FP16/BF16: FP8 on Hopper, NVFP4/MXFP4 on Blackwell, INT8/INT4 software paths. Cuts memory and bandwidth — the main lever for cheaper inference. → LLM Inference · Part 7
Structured output
Constraining model output to a valid JSON Schema (OpenAI Responses API, Anthropic, Gemini all support a flavor). Implemented as constrained decoding using a grammar/FSM (xgrammar, Outlines, lm-format-enforcer). → AI Engineering · Part 4
Evals
Quantitative test suites for LLM systems — golden sets, LLM-as-judge graders, trajectory rubrics. Treated as a first-class CI artifact in mature teams. Tools: Braintrust, Langfuse, Inspect AI, Promptfoo. → AI Engineering · Part 12

Agentic AI

Agent loop
The core perceive→plan→act→observe cycle: model emits a tool call, runtime executes it, result is fed back, repeat until the model declares done or a safety stop fires. → Agentic AI · Part 1
ReAct
Interleaved reasoning + acting trace where the model alternates "Thought" → "Action" → "Observation" steps. The original general-purpose agent pattern; still useful as a fallback when planning isn't worth the upfront cost. → Agentic AI · Part 2
Plan-and-execute
Generate an explicit multi-step plan first, then execute steps (often in parallel) with a re-plan trigger if a step fails. Better for governance: the upfront plan is reviewable. → Agentic AI · Part 2
MCP Model Context Protocol
Open standard (JSON-RPC over stdio/HTTP) for connecting LLMs to tools and data. Introduced by Anthropic Nov 2024; adopted by OpenAI Mar 2025, Google Apr 2025, Microsoft May 2025, AWS Nov 2025. Donated to the Linux Foundation (Agentic AI Foundation) Dec 2025. 10K+ public servers. → Agentic AI · Part 5
A2A Agent-to-Agent
Protocol for direct agent-to-agent communication and delegation. Originated at Google in 2025; supported by AWS AgentCore at GA. → Agentic AI · Part 9
Subagents
Lightweight delegated agents spawned from a parent agent for a focused sub-task with their own context window. Popularized by Anthropic's Claude Code in 2025; central to the Claude Agent SDK. → Agentic AI · Part 7
Tool use / Function calling
Model emits a structured call (name + arguments) into a registered toolset; the runtime executes and returns the result. Schema differs per provider — OpenAI Responses, Anthropic input_schema, Gemini function calling. MCP standardizes this across vendors. → Agentic AI · Part 4
Computer use / Browser agents
Agents that operate a real browser or desktop via screenshots + keyboard/mouse actions. Anthropic Computer Use, OpenAI Operator, Gemini browser agents. AgentCore Browser is the managed AWS surface. → Agentic AI · Part 4
AgentCore
AWS's managed runtime for production AI agents. Preview Jul 16 2025, GA Oct 13 2025, 9 regions. Seven services: Runtime, Memory, Identity, Gateway, Code Interpreter, Browser, Observability. Framework-agnostic; A2A protocol at GA. → AWS · Part 11 · Agentic AI · Part 11
Claude Agent SDK
Anthropic's official agent framework (2025). Native MCP, subagents as first-class, native memory tool. The conceptual model behind Claude Code generalized into a library. → Agentic AI · Part 10
Strands Agents SDK
AWS-built open-source agent framework. Pairs naturally with AgentCore (Strands = framework, AgentCore = runtime). → AWS · Part 11
ADK Agent Development Kit
Google's open-source agent framework, paired with Vertex AI Agent Builder. → GCP · Part 11
Memory tool
Model-native primitive for reading and writing persistent agent memory across sessions. Anthropic memory tool, OpenAI Responses API stateful sessions, LangGraph checkpointers, AgentCore Memory, Mem0. → Agentic AI · Part 6
Guardrails
Input/output filters around an LLM call — denied topics, content filters, PII redaction, contextual grounding, prompt-injection detection. Bedrock Guardrails, Azure Content Safety, Vertex Safety Filters; OSS via Llama Guard, NeMo Guardrails. → Agentic AI · Part 13

LLM inference

vLLM
Throughput-oriented open-source LLM serving engine. Introduced PagedAttention; the default high-concurrency engine for many deployments. Supports continuous batching, prefix caching, multi-LoRA, FP4 on Blackwell. → LLM Inference · Part 12
TensorRT-LLM
NVIDIA's optimized inference runtime. Best Blackwell FP4 support (NVFP4 native in v0.17+); deepest hardware integration. Uses ModelOpt for PTQ calibration. → LLM Inference · Part 12
SGLang
Serving engine with RadixAttention — radix-tree-based prefix caching that hits across requests. Strong for agent workloads with shared system prompts. → LLM Inference · Part 12
PagedAttention
KV cache stored in fixed-size pages mapped from a per-sequence page table — analogous to OS virtual memory. Lets the engine pack many sequences into the same GPU without internal fragmentation. → LLM Inference · Part 6
FlashAttention-3
Tiled, IO-aware fused attention kernel. FA-3 is the 2026 standard: Hopper-optimized, supports FP8, used everywhere serious. → LLM Inference · Part 8
Prefix caching
Reuse the KV cache of a shared prompt prefix across requests. Hash-keyed (vLLM) or radix-tree (SGLang RadixAttention). Critical for agents and chat where system prompts repeat. → LLM Inference · Part 11
Speculative decoding
A small "draft" model proposes a few tokens; the target model verifies in parallel. Acceptable tokens are committed for free. Modern variants: EAGLE-2/3 (learned draft head sharing target's hidden states), Medusa-2 (multi-head draft). → LLM Inference · Part 9
Chunked prefill
Slice a long prefill into chunks and interleave them with decode steps of other in-flight requests. Smooths tail latency. Sarathi-Serve formalized the schedule. → LLM Inference · Part 5
Disaggregated serving
Separate hardware pools for prefill (compute-bound) and decode (memory-bandwidth-bound). KV cache is transferred between them over NVLink/IB. Used at scale by DeepSeek; references: Splitwise, DistServe, Mooncake, NVIDIA Dynamo. → LLM Inference · Part 11
NVFP4 / MXFP4
4-bit floating-point formats with native Blackwell tensor core support. Both use E2M1 element encoding. NVFP4: 16-element blocks with FP8 (E4M3) micro-scale plus FP32 per-tensor — finest granularity. MXFP4: 32-element blocks with FP8 (E8M0) scale; broader kernel support including training. → LLM Inference · Part 7
MoE Mixture of Experts
Sparse architecture where a router activates only a few "expert" FFN blocks per token. Total params huge, active params small. Serving needs expert parallelism (EP) and careful all-to-all comm; DeepSeek-V3/R1 and Mixtral are canonical references. → LLM Inference · Part 10
GQA Grouped-Query Attention
Multiple Q heads share each KV head. Shrinks KV cache (and KV bandwidth) by 4-8× with negligible quality cost — the standard since Llama 3.x. → LLM Inference · Part 16
Multi-LoRA serving
Serve many LoRA adapters off one base model, swapping adapters per request or batching across adapters. References: S-LoRA, Punica. → LLM Inference · Part 11

Cloud AI services

Amazon Bedrock
AWS's foundation-model API. Current catalog includes Claude Opus 4.7 / Sonnet 4.6 / Haiku 4.5, Nova (Pro/Lite/Micro/Canvas/Reel), Llama, Mistral, Cohere, DeepSeek, AI21, Stability AI. Bundles Knowledge Bases (RAG), Guardrails, Agents (legacy), AgentCore. → AWS · Part 11
SageMaker HyperPod
AWS distributed FM training platform. Slurm or EKS orchestration, auto-recovery from hardware failures, Blackwell GB200 NVL72 UltraServers, recipes for Llama 3.1 405B, 3.2 90B, Mixtral, Nova. Elastic training GA Dec 2025. → AWS · Part 11
Trainium2 / Inferentia2
AWS-designed accelerators: Trainium2 for training (Trn2 UltraServers), Inferentia2 for inference. Programmed via the Neuron SDK. → AWS · Part 11
Azure AI Foundry
Azure's umbrella for AI app/agent dev. Renamed from Azure AI Studio in Nov 2024. Includes model catalog (Llama, Mistral, Phi, DeepSeek), Foundry Agents Service, prompt flow, evaluation, content safety. → Azure · Part 11
Azure AI Search
Hybrid + vector search service (renamed from Cognitive Search). HNSW or exhaustive KNN, integrated vectorization, agentic retrieval, semantic reranker. → Azure · Part 11
Phi family
Microsoft's flagship small language models — Phi-3, Phi-3.5, Phi-4. Optimized for on-device and edge inference. → Azure · Part 11
ACA Serverless GPU
Azure Container Apps serverless GPU (NVIDIA A100/T4). GA April 2025. Scale-to-zero, per-second billing, NVIDIA NIM support. → Azure · Part 4
AKS Automatic
Managed Kubernetes mode with opinionated defaults (Cilium, Karpenter, NGINX ingress, Azure Linux). GA September 2025. → Azure · Part 4
Vertex AI
Google's managed ML/GenAI platform. Hosts Gemini 2.5/3, Gemma 2/3, Imagen 3, Veo 2/3, Claude (via partnership), Llama. Bundles Model Garden, tuning, evaluation, prompt caching. → GCP · Part 11
Vertex AI Agent Builder + ADK
Google's agent stack: Agent Builder as the managed runtime, ADK as the open-source framework, A2A protocol for inter-agent calls. → GCP · Part 11
Cloud Run GPU
GCP serverless GPU inference (NVIDIA L4, RTX Pro 6000 Blackwell). GA June 3 2025. Scale-to-zero, per-second billing, ~5s cold start, no quota for L4. → GCP · Part 5
BigQuery vector search
VECTOR_SEARCH() with vector indexes inside BigQuery, plus BQ ML ML.GENERATE_TEXT remote models calling Gemini. Lets RAG live next to the data warehouse. → GCP · Part 10
AlloyDB AI
Postgres-compatible Spanner-class DB with ScaNN vector indexes and built-in model integration. → GCP · Part 7
Prompt caching
Caching the KV state of a stable prompt prefix at the provider. Anthropic explicit cache_control gives ~90% discount on cached tokens; OpenAI implicit ~50%; Gemini has both implicit and explicit context caching. Single biggest cost lever for chat and agent workloads. → Cloud AI Comparison · Part 10

Hardware

H100 / H200
NVIDIA Hopper datacenter GPUs. H100: 80 GB HBM3. H200: 141 GB HBM3e with ~1.4× the bandwidth — same compute, much better LLM serving. Native FP8 tensor cores. → LLM Inference · Part 3
B200 / GB200 NVL72
NVIDIA Blackwell. B200: 192 GB HBM3e, native NVFP4/MXFP4 tensor cores (~20 PFLOPS dense FP4). GB200 NVL72: 72 Blackwell GPUs in a single NVLink domain — eliminates cross-node hops for trillion-parameter models. → LLM Inference · Part 3
MI300X / MI325X
AMD CDNA3 datacenter GPUs. MI300X: 192 GB HBM3. MI325X: 256 GB HBM3e. The credible non-NVIDIA inference option in 2026, ROCm-based. → LLM Inference · Part 3
TPU v6e Trillium
Google's 6th-gen TPU. GA Q4 2024. 32 GB HBM, 256-chip pods, 4.7× compute per chip vs v5p, 67% better TOPS/W. Used to train Gemini 2.0. Only the v6e SKU exists — no v6p. → GCP · Part 11
TPU v7 Ironwood
Google's 7th-gen TPU, GA Nov 2025. 192 GB HBM3e, 7.37 TB/s memory bandwidth, FP8 native, 9,216-chip superpods (42.5 ExaFLOPS). Inference-optimized; powers Gemini 3 inference. Anthropic committed to 1M+ Ironwood chips for Claude training/serving in 2026. → GCP · Part 11
NVLink / NVSwitch
High-bandwidth GPU-to-GPU interconnect (5th-gen NVLink in Blackwell: 1.8 TB/s per GPU). NVSwitch fabric extends it to many GPUs in one coherent domain. → LLM Inference · Part 10
HBM3e
High-Bandwidth Memory generation used on H200, B200, MI325X, Ironwood. The bandwidth (~5-8 TB/s per stack on flagship) is the limit for memory-bandwidth-bound decode workloads. → LLM Inference · Part 3

System design

CAP theorem
Under a network partition, a system can preserve at most two of consistency, availability, and partition tolerance. The famous "pick 2 of 3" framing is misleading — partitions are unavoidable, so the real choice is C vs A during a partition. → System Design · Part 3
Raft
Leader-based consensus protocol — picks a leader, replicates a log to followers, commits when a majority acknowledges. Used by etcd, Consul, CockroachDB, TiDB. Multi-Paxos is the older, harder-to-implement alternative; Zab is ZooKeeper's variant. → System Design · Part 14
Saga
Pattern for distributed transactions: a sequence of local transactions, each with a compensating action. Choreography (each service reacts to events) vs orchestration (a coordinator drives steps). → System Design · Part 11
Idempotency key
Client-supplied unique token attached to a request. The server records it on first success and short-circuits duplicates — the safe basis for retries. Standard on Stripe, AWS APIs, etc. → System Design · Part 11
OpenTelemetry OTel
Vendor-neutral observability standard for traces, metrics, and logs. Has supplanted bespoke instrumentation (Jaeger client, X-Ray SDK). Backends are interchangeable: Tempo, Honeycomb, Datadog, Grafana stack. → System Design · Part 12
W3C traceparent
HTTP header standard for propagating distributed trace context across service hops. Format: 00-{trace-id}-{span-id}-{flags}. → System Design · Part 12
CDC Change Data Capture
Streaming row-level database changes from the transaction log into a downstream system. Debezium and Maxwell are the canonical tools; underpins the transactional outbox pattern. → System Design · Part 8
Vector database
Storage + ANN index optimized for high-dimensional similarity search. Postgres pgvector, Pinecone, Weaviate, Qdrant, Milvus. Inside warehouses: BigQuery VECTOR_SEARCH, AlloyDB AI, Spanner vector search. → System Design · Part 14
GCRA Generic Cell Rate Algorithm
Memory-efficient token-bucket/leaky-bucket variant from ATM networking. Stores just one timestamp per limit key — preferred in distributed rate limiters (Redis-backed) for that reason. → System Design · Part 13
SLO / Error budget
A Service Level Objective is a quantitative reliability target (e.g., 99.9% over 30 days). The error budget is what remains — feature work slows or pauses when it's exhausted. The discipline that prevents "fix vs ship" from being a vibes argument. → System Design · Part 12
Distributed SQL
SQL DBs with horizontal scale built in: Spanner, CockroachDB, Vitess, YugabyteDB, TiDB, PlanetScale, Neon. Removes the historical "SQL only scales up" framing. → System Design · Part 6
Rate limiting algorithms
Fixed window, sliding window, token bucket, leaky bucket, GCRA. Adaptive concurrency limits (Netflix Concurrency Limits, AIMD) target throughput instead of rate — distinct from load shedding. → System Design · Part 13

Python

PEP 695 generics
New generic syntax (3.12+): def first[T](items: list[T]) -> T:, class Box[T]:, type Alias = .... Replaces the old TypeVar("T") + Generic[T] dance. → Python · Part 14
PEP 703 / free-threaded
No-GIL build of CPython. Experimental in 3.13 (~40% single-thread overhead); officially supported in 3.14 via PEP 779 (~5-10% overhead). Still an optional build — not the default. → Python · Part 15
PEP 744 / JIT
Tier-2 copy-and-patch JIT, experimental since 3.13. Not yet enabled by default. → Python · Part 17
asyncio.TaskGroup
Structured concurrency primitive (3.11+). async with asyncio.TaskGroup() as tg: tg.create_task(...). If any task fails, siblings are cancelled and exceptions surface as a group. Now the recommended pattern over gather. → Python · Part 15
asyncio.timeout
Async timeout context manager (3.11+). async with asyncio.timeout(5): — cleaner than wrapping in wait_for. → Python · Part 15
uv
Astral's fast Rust-based Python package/venv/project manager. Replaces pip + virtualenv + pip-tools and increasingly poetry/pdm. uv venv, uv add, uv run, lockfile via uv.lock. → Python · Part 0
ruff / ruff format
Astral's Rust-based linter (replaces flake8/pylint/isort) and formatter (now displacing black). One tool, fast. → Python · Part 16
Pydantic v2
Runtime data validation tied to type hints — the standard in 2026 for API boundaries, agent tool schemas, structured LLM output. → Python · Part 14
tomllib
Stdlib TOML reader (3.11+). Use for parsing pyproject.toml and config files without a third-party dependency. → Python · Part 13

DSA

Union-Find / DSU
Disjoint-set data structure with path compression and union-by-rank-or-size. Near-O(1) amortized. Used for connected components, Kruskal's MST, redundant connection, accounts merge. → DSA · Part 13
Trie
Prefix tree for string sets with character-by-character traversal. insert, search, startsWith all O(L) for a string of length L. Foundation for autocomplete, Word Search II. → DSA · Part 3
Topological sort
Linear ordering of a DAG such that for every edge u→v, u appears before v. Kahn's BFS: queue all in-degree-0 nodes, peel them off, decrement neighbors. Detects cycles when the ordering is short. → DSA · Part 13
Monotonic stack / queue
Stack or deque maintained in monotonic order to answer "next greater / next smaller element" or sliding-window max/min in amortized O(n). → DSA · Part 7
Quickselect
Partition-based selection of the k-th element. Average O(n), worst O(n²). Faster than the heap approach for one-shot k-th-largest problems. → DSA · Part 14
Kadane's algorithm
O(n) maximum subarray sum DP. Maintain "best ending here" and "best so far"; reset when running sum goes negative. → DSA · Part 15
Dijkstra's algorithm
Shortest path in a weighted graph with non-negative edges. Min-heap of (distance, node), pop the smallest, relax neighbors. O((V+E) log V). For negative edges use Bellman-Ford. → DSA · Part 13
LRU cache
Eviction policy: drop the least-recently-used entry. Implemented as ordered-dict (Python) or doubly-linked list + hashmap (interview classic). In Python: @functools.lru_cache for pure functions. → DSA · Part 14
Sliding window
Two-pointer technique over an array/string. Expand the right pointer, shrink the left when an invariant breaks. Most "longest substring with X" problems collapse to it. → DSA · Part 8
